## 1. 启动 dist

```powershell
# 推荐：server 模式（固定端口，便于脚本探活）
node dist/app.js server 8080
```

- [ ] 进程常驻，终端出现 HTTP listen / online（无 bootstrap 致命退出）
- [ ] 引导日志：`logs/bootstrap.log` 无启动即崩的堆栈

备选：`pnpm start`（菜单）或 `XRK_SERVER_PORT=8080 node dist/app.js`。

---

## 2. 探活 API

将 `$PORT` 换成实际端口（下例 8080）：

```powershell
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:8080/health
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:8080/status
curl.exe -s http://127.0.0.1:8080/api/health
```

| 路径 | 期望 | 备注 |
|------|------|------|
| `GET /health` | **200** | 存活（compose healthcheck 同此） |
| `GET /status` | **200** | 运行时摘要 |
| `GET /api/health` | **200**（就绪） | Redis/SQLite 任一 `down` → **503 unhealthy** → 停发 |

- [ ] `/health`、`/status` 为 200
- [ ] `/api/health` 为 200，且 `services.redis` / `services.sqlite` 非 `down`

可选：`GET /api/plugins/summary` → 200 + `success`（与 E2E 同口径）。

pnpm exec node --test tests/framework/agt-ai-surfaces.test.mjs

- [ ] 含 `HARNESS_SDK_PIN matches package.json and installed SDK` 在内 **全绿**

```powershell

```

- [ ] `GET`/`POST` 模型或一次极短 `/v1/chat/completions` 非 5xx（配置缺失 → 4xx 可接受，但勿 5xx 风暴）

## 5. 日志无 error 风暴

观察窗口：启动后 **3–5 分钟** 稳态（含完成上述探活）。

| 位置 | 看什么 |
|------|--------|
| 终端 stdout/stderr | 无同文案秒级重复刷屏 |
| `logs/*.log`（含 `bootstrap.log`、PM2 `pm2_server_*`） | 无连续 ERROR / uncaught / ECONNREFUSED 风暴 |

- [ ] 无「同一错误 ≥10 次 / 分钟」级刷屏
- [ ] 无未捕获异常导致进程重启循环
- [ ] 已知 degraded（如可选子服探活失败）仅单条 warn，不拖垮主服
